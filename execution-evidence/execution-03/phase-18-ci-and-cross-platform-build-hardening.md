## Task 144 — Caching audited, no change needed

Both new workflows cache `~/.cargo/registry`/`~/.cargo/git`/`target`
keyed on `hashFiles('**/Cargo.lock')` -- the identical pattern
`ci.yml` already uses. Audited for the real risk this task names
("hide stale Wasm/native artifacts"): a restored cache from an earlier
commit with the same `Cargo.lock` could contain an older
`target/wasm32-unknown-unknown/**/craftloop_web_bridge.wasm`, but
Cargo's own fingerprinting is content-based (not just cache-key- or
mtime-based) -- `cargo build` recompiles and overwrites that exact
file the moment the real source differs from what the fingerprint
recorded, regardless of what the GitHub Actions cache key matched.
The wasm-bindgen-generated JS/TS output itself (`apps/web-live/src/
wasm-bridge`) is never cached at all in CI -- it is gitignored and
freshly regenerated by `npm run build`'s `prebuild` hook on every run,
the same real script (`build-wasm-bridge.mjs`) whose own
`rmSync`-before-write already prevents a stale partial write locally
(Phase 17). No caching change was needed; the existing pattern is
already safe by construction, verified by tracing through it rather
than assumed.

## Task 146 — License audit

Ran a real audit (`npx license-checker --summary --excludePrivatePackages`)
against `apps/web-live`'s full installed dependency tree (126
third-party packages; the workspace's own `private: true` package was
excluded, not silently miscounted as a real "UNLICENSED" finding):

```
MIT: 104        BSD-2-Clause: 2     BlueOak-1.0.0: 1
Apache-2.0: 8    MPL-2.0: 2          CC0-1.0: 1
ISC: 4          BSD-3-Clause: 2
```

Every license is a standard, permissive (or, for the two MPL-2.0
packages, weak-file-level-copyleft) OSS license -- no GPL/AGPL/other
strong-copyleft dependency anywhere in the tree. The two MPL-2.0
packages (`lightningcss`, `lightningcss-win32-x64-msvc`) are Vite's
own transitive build-time CSS tooling, used unmodified as a build
dependency, not redistributed/modified source -- no obligation flows
from MPL-2.0's file-level copyleft in that usage. Re-running
`npx license-checker --excludePrivatePackages --onlyAllow
"MIT;Apache-2.0;ISC;MIT-0;BSD-2-Clause;BSD-3-Clause;MPL-2.0;BlueOak-1.0.0;CC0-1.0"`
exits `0` (no violation), confirming the summary programmatically, not
just by eye.
