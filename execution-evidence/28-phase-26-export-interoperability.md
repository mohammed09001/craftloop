# Phase 26 — Export and Diagnostic Interoperability — Evidence

Recorded: 2026-09-13

New crate: `crates/craftloop-export`. A new crate rather than an
extension of `craftloop-document`, matching Phase 25's precedent: export
is a presentation/output concern layered on top of the document's entity
model, not part of the model itself. Depends on `craftloop-document`,
`craftloop-dimension`, `craftloop-standards` (Phase 25, for `LineRole`
styling and `DimensionTypography`), `craftloop-units`, and the lower-level
geometry/ink/recognition crates each entity kind is built from. Added one
new structured error variant, `DomainError::Export`/`ExportErrorKind`
(`crates/craftloop-errors/src/lib.rs`), following the exact namespaced
pattern every earlier subsystem error uses.

## Task 186 — Semantic JSON diagnostic export

`diagnostic_json.rs`: `diagnostic_export`/`export_diagnostic_json`. Not a
duplicate of `craftloop_document::persistence`'s round-trip save format
(Phase 07) -- that format is compact storage; this one denormalizes each
entity's `ProvenanceState` inline next to the entity it describes (storage
keeps them in two separate structures, requiring a join to read
together), for a developer reading the export directly or pinning it as a
regression fixture. Deliberately unfiltered: conflicts and not-yet-removed
command ink both appear, proven directly by
`a_mixed_document_exports_consistently_across_every_target` in the new
integration test.

## Task 187 — SVG export

`svg.rs`: `export_svg`. Renders visible ink, beautified geometry (line/
circle/arc/rectangle, styled via `craftloop_standards::style_for_role`),
notes, and dimension value text into a single self-contained SVG document.
Documented explicitly, in the module's own doc comment, that native
engineering semantics (constraint state, `DimensionRole`, provenance) do
not survive generic SVG -- a viewer sees shapes and text only. Dimension
rendering is bounded to a text label at the annotation's position: no
phase through 26 has built real dimension-line/extension-line-to-feature
projection geometry, so a full leader-line drawing is out of scope, named
as such in the module doc rather than silently approximated.

## Task 188 — PDF export path or bounded prototype

`pdf.rs`: `export_pdf_bounded`. A full third-party PDF library is not a
verified Execution 01 dependency (license/build footprint unchecked for
this workspace's platforms), so per the task's own escape hatch this
module hand-writes a minimal, valid single-page PDF directly: real
`xref` byte offsets, a real `/Length` value, no external crate. Bounded,
documented fidelity limits: circles/arcs are approximated as 48-sided
polygons (not true PDF Bezier curves), coordinates pass through as
millimeters with no mm-to-point scaling or y-flip (same convention as
`svg::export_svg`, internally consistent but not print-scale-accurate),
and text uses the base-14 Helvetica font with no non-ASCII guarantee.
Proven structurally correct, not just "looks right": one test parses the
`xref` table back out of the generated bytes and confirms every offset
points at the real byte position of its own `N 0 obj` header; another
confirms the declared `/Length` exactly matches the stream's real byte
count.

## Task 189 — Preserve units and visible annotation values

No dedicated module: proven directly inside `svg.rs` and `pdf.rs`, and
again at the integration level. A dimension is stored canonically as
25.4mm (Phase 09's millimeter-canonical policy); with the document's
display unit set to `Inches`, both exports are asserted to contain the
converted text `"1.000in"` and to **not** contain the raw `"25.4"`
anywhere in their output -- a real, positive proof against accidental
rescaling, not just an absence-of-error check.

## Task 190 — Exclude ephemeral interaction ink

`visible_entities.rs`: `is_export_visible`/`visible_entities`, the one
filter both `svg` and `pdf` call through, so the exclusion rule cannot
drift between the two targets. Two things are excluded: strokes named in
an `ephemeral_strokes` set (the caller's real source is
`craftloop_command::EphemeralInkDisposition::strokes_to_remove`, Phase
19 -- exercised directly in the integration test, not just asserted by
convention) and `SemanticEntity::Conflict` entities (diagnostic overlays,
never part of the drawing itself). The developer diagnostic export (Task
186) deliberately does not use this filter.

## Task 191 — Defer DXF until fidelity is proven

No DXF module exists in this crate. `UNSUPPORTED_EXPORT_TARGETS`
documents the decision explicitly (matching
`craftloop_standards::UNSUPPORTED_CONVENTIONS`'s Phase 25 pattern):
DXF needs entity-section conventions (layers, block references, exact
`TABLES`/`ENTITIES` structure) this execution cannot currently verify
fidelity for against a real CAD tool, and shipping a partial writer that
opens but silently misrepresents geometry would be exactly the
"misleading partial implementation" the task forbids. A test
(`no_dxf_export_function_exists_in_this_crate`) marks the decision as
findable from the test suite, not only from documentation.

## Errors and fixes

- Two import errors on first compile: `DimensionTypography` was imported
  from `craftloop_dimension` in both `svg.rs` and `pdf.rs`, but it is
  defined in `craftloop_standards` (Phase 25). Fixed by correcting the
  import path in both files.
- `PointerSource::Pen` does not exist (the real variants are
  `SimulatedMouse`/`Stylus`/`Touch`, Phase 03); used in three test
  fixtures across `visible_entities.rs`, `svg.rs`, and `pdf.rs`. Fixed by
  using `PointerSource::Stylus`.
- Four clippy findings, all in test code, all mechanical: `clone_on_copy`
  on `PointerSample` (a `Copy` type) in two files, `needless_borrow`
  passing `&page` where `page: &Page` already, and
  `cloned_ref_to_slice_refs` where `std::slice::from_ref` is the correct
  idiom. All fixed; no production-code findings.
- No test-correctness bugs found this phase (unlike Phases 19/22/24):
  every test in `visible_entities.rs`, `diagnostic_json.rs`, `svg.rs`,
  `pdf.rs`, and the integration suite passed on its first real run once
  the crate compiled.

## Deferred, explicitly

- DXF export (Task 191's own subject) -- see above.
- STEP/IGES 3D exchange formats -- this product's document model is 2D;
  out of scope for any phase reached so far.
- Multi-page PDF -- the Task 188 prototype writes exactly one page.
- Full dimension leader-line/extension-line geometry in SVG/PDF -- no
  phase has built feature-to-annotation projection geometry yet; only the
  presented value text renders.
- True PDF Bezier curves for circles/arcs, and mm-to-point physical-scale
  conversion for the PDF prototype -- named as explicit prototype
  limitations in `pdf.rs`'s own module documentation.
